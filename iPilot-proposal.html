01 背景与目标

Codex Build iOS Apps Plugin 已经实现了 Simulator 内的完整开发闭环：构建、运行、投屏到浏览器、UI 自动化、选择元素 Annotation + Ask AI。但它止步于 Simulator——真机场景完全空白。

iPilot 做同一件事，但操作真机：同样以 Codex Plugin 形态发布，复用 Skills 体系，在 Codex 右栏显示设备画面。Annotation / Ask AI 由 Codex 平台原生能力提供，Preview 页面只需要呈现好截图和 DOM 框即可。

02 核心设计原则

Codex Hooks 驱动 · ios-use 零改动 · Agent 零感知 · 单文件逻辑
  • Codex PostToolUse Hook：利用 Codex CLI 原生的 hooks.json 系统，在 PostToolUse 事件中匹配 ios-use 命令。命令执行后自动截图 + DOM → 写入固定路径。不需要修改 ios-use 代码，Agent 使用方式零改变。
  • device-preview.mjs 一个文件两个角色：作为 PostToolUse hook handler（匹配 ios-use → 截图+DOM），同时作为 Preview HTTP Server（fs.watch → SSE → 截图+DOM框渲染）。全部逻辑集中在一个文件。
  • Annotation 靠 Codex：用户在 Preview 中选择元素/区域并添加 annotation 的能力是 Codex 平台原生提供的，Preview 页面不需要实现任何 → chat 的通信桥。

04 关键组件

4.1 hooks.json — 通过 plugin.json 自动注册

利用 Codex CLI 原生 Hooks 系统，不修改 ios-use。hooks.json 放在插件根目录，plugin.json 中声明 "hooks": "./hooks.json"，安装插件时自动注册，用户无需手动配置。

// .codex-plugin/plugin.json（摘录）
{ "hooks": "./hooks.json" }

// hooks.json（插件根目录）
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "node $PLUGIN_DIR/skills/ios-device-preview/scripts/device-preview.mjs hook",
        "timeout": 30
      }]
    }]
  }
}

4.2 device-preview.mjs — 一个文件两个角色

所有逻辑集中在一个文件。不需要修改 ios-use 源码。

角色 1: Hook Handler

PostToolUse 拦截

node device-preview.mjs hook：stdin 读取 Codex 传入的 tool 调用信息 → 正则匹配 ios-use (tap|swipe|input|longpress|home|dom|...) → 匹配成功则执行 ios-use screenshot + ios-use dom → 写入 ~/.ipilot/。匹配失败则 exit 0。

角色 2: Preview Server

HTTP + SSE 展示

node device-preview.mjs serve：fs.watch('~/.ipilot/') 监听截图+DOM 文件变化 → SSE 推前端 → <img> 底图 + SVG DOM 框叠加渲染。localhost:3200。

4.3 Annotation / Ask AI

Codex 平台原生能力，不需要 iPilot 实现。用户在右栏 Preview 页面中选择元素或区域 → 添加 annotation → 自动注入 Agent 聊天上下文。Preview 页面只要正确渲染截图和 DOM 框，Codex 的 annotation 系统就能自动工作。

4.5 Snapshot 数据结构

// ~/.ipilot/snapshot.json（ios-use hook 自动输出）
interface DeviceSnapshot {
  screenshot: string;       // 截图文件路径（snapshot.png）
  dom: DOMElement[];        // ios-use dom 的 AX 树
  timestamp: number;
}

interface DOMElement {
  ref: string;              // ios-use 的 ref id
  type: string;             // Button, TextField, StaticText...
  label?: string;
  value?: string;
  bounds: { x: number; y: number; w: number; h: number };
  children?: DOMElement[];
}

05 典型工作流

场景 A · Agent 操作 + Preview 自动更新

用户在 Codex 聊天中说「把首页登录按钮改成圆角并验证」。
Agent 修改 Swift 代码 → xcodebuild -sdk iphoneos 构建 → 安装到真机。
Agent 调 ios-use tap "登录"（正常使用，无额外步骤）。
ios-use hook 自动截图+DOM → Preview Server 自动推送 → Codex 右栏立即更新。
Agent 读 ios-use dom 返回值确认按钮属性 ✅。用户在右栏看到最新截图。

场景 B · 用户 Annotation Ask AI

用户在 Codex 右栏 Preview 中看到真机截图 + DOM 框。
用户通过 Codex 原生 Annotation 功能，圈选某个元素/区域，添加注释如「这个按钮颜色不对」。
Codex 自动将 annotation（含截图区域 + 用户文字）注入到 Agent 聊天上下文。
Agent 基于信息修改代码 → 重新构建 → ios-use 操作 → Preview 自动刷新。

场景 C · 性能分析

用户说「分析一下首页列表滚动卡顿」。
Agent 临时 link ETTrace → 构建安装 → 提示用户在真机上操作。
ettrace --launch --dsyms 采集 → 火焰图 JSON → 自动分析热点函数。
Agent 报告热点函数 + 百分比 + 修复建议。

08 部署与依赖

硬件

Mac（mini/Studio）+ USB 真机 iPhone（开启开发者模式）。

软件依赖

Codex CLI、Node.js 18+、Xcode 15+、ios-use CLI（无需改动）、ettrace (Homebrew)。

安装

codex plugin install iPilot 或 clone 后 Codex 自动识别 .codex-plugin/。

真机准备

ios-use 首次 config --udid 安装驱动。Codex Hooks 自动生效，无需额外配置。
